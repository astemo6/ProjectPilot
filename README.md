## v3：里程碑计划与执行计划合并为一个项目
- 入口 `index.html`：一个页面、一个项目，顶栏切换「项目甘特图」和「客户节点」两个视图。
- 客户节点自动成为项目甘特图最上面的里程碑行（固定约束，不被依赖推移），下面接推荐任务、供应商节点、自定义任务和你自己的任务。
- 实时联动：
  - 在「客户节点」改日期 → 项目甘特图里的里程碑和推荐任务立即跟着变；
  - 在项目甘特图里改客户里程碑 → 节点日期自动回写；
  - 工作日历两边共用，改一边另一边立即生效。
- 增量同步，不再整表重建：你加的任务、负责人、输出成果、进度、备注、依赖全部保留；手动改过日期的推荐任务保持你的日期。
- 修复：旧执行页每次刷新都会按计划重建任务，手动添加的任务会丢；现在刷新不丢。
- 「导出项目 / 导入项目」：一个 JSON 包含客户节点、任务、工作日历；兼容旧版里程碑计划 JSON 和执行页 JSON。
- 「客户节点」视图的 PDF/JPG 导出即给主机厂的节点报告；项目甘特图的导出是完整执行计划。
- 已合入原仓库 gantt-tool 截至 52fe4fc 的更新：APQP / VDA-MLA / ANPQP 交付物模板（插入时开始日避开非工作日；ASTEMO 摩擦件模板也放进「模板」菜单）、MS Project XML 导入导出（导入后保留客户节点行）、带甘特图的 Excel（.xls）导出。

# 客户节点甘特图工具 v2

基于 [astemo6/gantt-tool](https://github.com/astemo6/gantt-tool) 的优化版（原仓库保持不变）。

- `index.html` 里程碑计划：选择主机厂 → 填写客户节点日期 → 自动生成甘特图（客户节点 + 阶段 + 13 项推荐任务 + 供应商节点 + 自定义任务）
- `exec.html` 执行层计划：工作日排程、FS/SS/FF/SF 依赖、关键路径、基线、资源预警、PDF/JPG 导出，可从计划页导入并回写里程碑
- `workcal.js` 两页共用的工作日历

## v2 改动

### 修复
1. **执行页自定义工作日历刷新后丢失**：原来节假日/调休只存在内存里，刷新页面或导入 JSON 后都会恢复默认，任务日期随之变化。现在保存到浏览器（`gantt-workcal-v1`），导出 JSON 带日历，导入时一并恢复。
2. **推荐任务落在周末/节假日，且计划页与执行页日期不一致**：原来推荐任务按"锚点 ± 周数"直接取自然日，可能从周六、中秋等非工作日开始；执行页导入时工期换算又会让结束日与计划页差 1~2 天（如 BMW 示例的 T1 试模、试生产准备）。现在两页按同一工作日历：开始日顺延、结束日提前到工作日；计划页把最终日期写入 `recComputed`，执行页直接采用，保证完全一致。
3. **执行页分组行显示"今天"作为开始日**：从计划导入或载入模板生成的分组行不再带当天日期，时间轴范围也不再被拉到今天。

### 新增
4. **工作日历四种模式**（执行页「工作日历」面板，计划页同步使用）：中国（法定节假日 + 调休，内置 2026 年安排）/ 德国（全国性法定假日，自动计算复活节相关假日，适合 BMW、奔驰等德系项目）/ 仅周末 / 关闭（自然日）。原有自然语言、文本格式的自定义放假和补班仍可叠加。
6. **任务表新增「输出成果」「备注」列**：输出成果默认显示，备注默认隐藏，可在「列」菜单切换；PDF/JPG 导出同步显示。
7. **计划页示例日期更贴近实际**：按该主机厂的标准节点间隔生成，今天大约落在项目的 40% 处，不再是均匀铺开。
